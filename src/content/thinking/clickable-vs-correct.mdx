## 观察

用户反馈了一句话：

> 好几个按键都用不了。

值得注意的不是这句话的内容，而是**「好几个」**这个词。如果是单个按钮坏了，反馈会是「XX 按钮点不了」；说「好几个」，说明这是一个面上失效，不是点上的 bug。

同一时间，我的自动化测试套件全绿 —— 1235 条断言，零失败。

## 假设

我怀疑测试本身有盲区。查下来发现关键在这一行：

```js
element.click();   // 绕过命中测试
```

`element.click()` 直接在元素上派发事件，**不检查该元素是否真的在最上层**。所以即使按钮被别的元素完全盖住，这行代码依然能触发它的回调。

结论：**「功能逻辑正确」和「手指点得到」是两个独立命题，而我的测试只覆盖了前者。**

## 怎么验证

不靠推理，补两类用真实事件路径的测试：

| 测试 | 做什么 | 断言数 |
| --- | --- | --- |
| `worklog-tap` | 用 CDP 派发真实鼠标/触摸事件，把「课表 → 导入课表 → 粘贴文字 → 解析 → 确认导入」整条路径走一遍 | 45 |
| `worklog-sweep` | 逐个打开 4 个页面 + 全屏导入页 + 7 个弹层，对最上层里每个可见按钮做命中测试；390 / 360 / 320 三种屏宽各跑一遍 | 40 |

然后用同一套脚本，对着线上旧版和本地新版各跑一次做对照。

## 结论

对照结果非常明确：

```
线上旧版：6 个按钮点不到
    「解析并加入列表」被 <footer.ov-foot> 盖住
    「保存」        被 <div#importBody> 盖住
    「保存，再添一门」被 <button#importConfirm> 盖住
    「关闭」/ 星期按钮 被 <div#importBody> 盖住

本地新版：40 通过 / 0 失败
```

留在 README 里的一句话是：

> **只要动了「谁盖在谁上面」，必须用真实点击验证，不能只看逻辑测试。**

推广一点：**测试覆盖的是你写下的假设，而不是用户的操作。** 1235 条断言全绿这件事本身没有错，错的是我把「测试全绿」当成了「用户能用」的证据。当断言数量和用户反馈冲突时，用户反馈是对的 —— 该改的是测试。
